## 1. この文書の使い方

マスタ・要件メモ・設計書・現行コード・tokensの間にある食い違いと、描かれていない状態を、設計書側で黙って解かずに挙げる。各項目は「どこで・今どう書かれているか・どうするか・なぜか」を持つ。

- 実装は、承認された「推奨」の採用値を使う。承認はgate 3に含める（採用値を変えたい項目は、Itsukiが確認1でBと理由を返す）。
- 「Figmaを直す」は、Frontが採用値をマスタへ反映する依頼。反映が遅れても実装は止まらない（採用値が正本）。
- 記号: 種別 A=マスタと設計書・要件メモ・コードの食い違い、B=描かれていない状態・画面、C=現行にあってマスタに無い情報、D=表記の対応（食い違いではなく、決めた対応を記録する）。
- Itsukiにしか決められない価値判断はこの文書に無い（VF3の「一覧に予約の枚数・未対応の件数を出すか」だけが確認1で確定する。`requirements.md` §8）。
- Figmaのサンプル（人名・会場名・件数・日付）は見本で、本番の事実ではない。この文書では見本の中身を引用せず、node-idと構造で示す。
