## 1. 目的と範囲

Itsukiが、Site・News・Music（作品と映像）・Profileの更新を、Liveと同じ操作の型（一覧と編集、保存して公開、未保存の確認）で、スマホからできるようにする。タブは Site / News / Live / Music / Profile の5つにする。Itsukiはこの道具をスマホで使い、mergeした時点で本番の道具が入れ替わる。この Issue は**保存の仕方を変える**ので、**保存を壊さないこと**（送る内容、データの形、ほかの項目の未保存の入力を巻き込まないこと）を最優先にする。

Itsukiの決定（2026-11-21）: Issueの「確かめていないこと」にある「項目の追加とタブの統合だけを先に行う進め方」は採らない。範囲を**全部、1つのcycle・1回のmergeで出す**。

対象は次のとおり（Issue #47の範囲、`audit.md` §1）。

- タブを5つにする（YouTubeとDiscoをMusicにまとめ、中で作品と映像を切り替える。Channel URLを含む）。
- News・作品・映像の編集を、画面下から開く編集面から、一覧と編集の2列（幅900px以上）／一覧→編集（スマホ）に変える。
- 保存を「更新でその場保存」と headerの「保存」から、各タブの「保存して公開」と未保存の確認に揃える。
- SiteとProfileを同じ見た目に揃える。
- 上の帯（Header）を、Liveのマスタの形（幅390pxは高さ46px・右に「接続中」）にする。

対象外は次のとおり。これらを変えないと満たせない要件が出たら、止めてFrontへ返す。

- Liveのタブの中身（一覧・ライブを開いた画面・予約・予約管理・Ticket Page共通設定。Liveの上の帯の形が変わることを除く）。
- 公開側のページ（#42〜#45）、公開APIの応答。
- データの形（公開データのJSONのキー・型・空の表し方、`id`の付け方、カテゴリ間で`id`を保つこと、#41の参照の照合）、Cloudflare Worker（変えない。deployもない）、DBのschema。
- 色・文字・余白の正本（`DESIGN_RULES.md`・`assets/css/1212-music.tokens.css`）。News・作品・映像への新しい必須項目の追加。

要件の正本は`docs/specs/current/live-operations-admin-ui.md`（§4.1、§4.4〜§4.6、§5.3、§6、§9、§10、§11.2、§12.3、§13.3、§14、§15）。Figmaはマスタ section `15:20`（要件メモ`39:817`、状態`39:741`、たまにする更新の10 frame、比較のLiveの`44:492`・`47:582`）。原典・読取範囲・SHA-256は`aidlc-docs/audit.md`。Figmaの題・人名・URL・件数は見本であり、本番の事実として採用しない。マスタ・設計書・現行コードの食い違いと、描かれていない画面・状態は`figma-fix-requests.md`（F47-01〜26）に挙げ、採用値を決めた。
